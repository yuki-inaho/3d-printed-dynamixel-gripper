# 全6関節XL430静止組立の受領レビュー 2026-09-19

## 受領物

対象は受領ZIP`low_cost_robot_all_XL430_CAD_20260919.zip`である。

```text
SHA-256: 848ea763de613280a87d0988260252e60682d40be1a8c200018e3cbb4e003fe7
```

ZIPには全XL430静止組立STEP、7種類のSTEP/STL、置換manifest、再読込記録、生成スクリプトが含まれていた。受領スクリプトは`/mnt/data/...`の固定パスと末端要素番号範囲に依存していたため、そのままでは別checkoutから再生成できなかった。

## リポジトリへの反映

再生成処理を`skills/cad-reverse-parametric/studies/all_xl430_revision/`へ分離した。

- 元入力はSHA-256で保護された`hardware/follower/step/arm.step`と`elbow_to_wrist_extension.step`。
- 置換対象は要素番号ではなく4つのアセンブリパスで特定する。
- 元から存在するXL430 2台を保持し、XL330系4台・84末端要素をXL430参照形状140末端要素へ置換する。
- 再生成結果は受領物と同じ217末端要素、同じ配置変換、同じ外形寸法になった。
- 置換後STEPを再読込してから、静止姿勢のB-rep体積干渉を独立に検査する。

生成物は`skills/cad-reverse-parametric/outputs/all_xl430_revision/unaccepted/current/`にある。組立STEPは`CAD/arm_all_XL430_static_UNACCEPTED.step`であり、承認済みCADではない。

主な重複は、J3相当とグリッパー側モーター相当のXL430同士、XL430と延長リンク、XL430とグリッパー固定・可動部、XL430と肩・手首ブラケットの間にある。ねじ接触だけではなくモーター本体を含む大きな体積重複なので、許容接触として扱わない。

## 受領説明との差分

受領説明にあった「静止姿勢の不適切な体積重複を解消」は、ZIPに収録された証跡からは全XL430組立について確認できなかった。`geometry_baseline_collisions.json`は、XL430 2台とXL330系4台を維持した**置換前の混在サーボ基準モデル**のレポートである。全XL430組立STEPに対して同じ検査を再実行すると54件の外部部品間干渉が検出された。

同様に「72か所の穴軸」を示す全XL430版レポートはZIP内にない。確認できた`geometry_baseline_validation.json`は、混在版の5締結パターン、合計18軸の結果である。72軸という数値は検証済み成果として引き継がない。

7種類の造形部品も、全XL430向けに再設計されたものではない。前回の混在サーボ幾何改訂で検証した7部品の流用であり、STLは同一だった。STEPのバイト列は再エクスポートにより異なるが、部品形状とSTLは混在版基準である。

## 完了判定

この作業で確認できたのは「全6台をXL430形状に置換した静止STEPを再現できる」ことまでである。「全XL430アームとして組み立てられる」「7部品を印刷して使用できる」ことは確認できていない。

`source/study.py print-package`（`prepare_print_package.py`は同じゲートを呼ぶ薄いラッパー）は、保存済みレポートを信用せず毎回`validate`を再実行し、外部干渉が0件になり、同一リビジョンの工学検証6項目（全XL430部品適合、連続動作、保持トルク、強度、締結・組立、実機嵌合）が揃うまで終了コード2で停止し、印刷物を生成しない。次の設計段階では、取付基準とねじスタックを定義したうえで7部品を局所修正し、置換後の穴軸、静止干渉、連続掃引干渉を順に再検査する。
