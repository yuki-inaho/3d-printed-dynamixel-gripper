# 横開きグリッパ・カメラマウント受領案のレビュー

レビュー日: 2026-09-22。判定: **現在の全XL430実機向けとしては差戻し。概念検討資料として保管。**
対象の形状・コードは変更していない。今回の作業は受領案の検証と改善方針の策定であり、改修完了ではない。

## 1. 重大な指摘と改善方針

### F-01 / P1: 全XL430という前提を満たしておらず、手首取付も互換ではない

受領案の基準はXL430×2とXL330系×4の混在アーム。手首の相手は
`/XL,XC-330 v1:6/DC15_A01_HORN_DUMMY:1` とコードで固定されている。
閉じ・開きで外部干渉ゼロでも、ユーザーの全XL430アームへの適合判定ではない。

保存STEPから測定した新フランジの四穴は**半径6 mm / PCD12 mm**。
手元のR3 CADの `M05_ref00` にあるXL430出力側四穴は**半径8 mm / PCD16 mm**。
回転軸を合わせても各穴の半径方向に少なくとも**2.0 mm**の不一致が残る。
これは配置比較ではなく、そもそもの穴パターン寸法の不一致である。
`M05_ref07` は反対側のidlerであり、この結論はそちらとの取り違えではない。
R3のJ5/M05を実機通信ID5と断定するものでもない。

改善: 全XL430の実際の取付先を基準に、出力軸・座面・四穴・相手リンク・必要支持幅を
一つの座標系で定義し直す。穴を大きくして2 mmのずれを吸収しない。
旧XL330ジョーの保持部もそのままXL430に使えると扱わない。
R3自体も全機能が製作承認されたモデルではないため、形状参照と合否を分ける。

根拠: 受領 `design.py:29`, `design.py:244`, `review.py:144`、
追加検証 `wrist-pattern-comparison.json`。

### F-02 / P1: 指定されていたリンク固定カメラと、取付先・動きが違う

直前の依頼はユーザー提供写真に対応するID4〜ID5間のリンク、
本リポジトリでは `P05_wrist_XL430.step` の中央板へカメラを固定するものだった。
受領案はそのリンクではなく、**手首ホーンとグリッパの間へ4 mm厚フランジを挟む**。
カメラが手首出力側と一緒に回り、工具長も4 mm増える。

これはカメラ位置の微調整ではなく、機構上の取付先と座標変換の変更である。
ロール時の画像回転、USBケーブルのねじり、TCP、外部パラメータに影響する。
ユーザーの承認なしにリンク固定と等価として採用してはいけない。

改善: まず「リンク固定」と「ロール追従」を別案に分ける。
既存依頼を維持する場合はP05固定を優先し、28×28 mmの交換式カメラ板のみを
共通化する。ホーンへの4 mm挿入をカメラ追加の必須条件にしない。
ロール追従を採るなら、変更理由とUSB配線の可動域を別途承認する。

根拠: 受領 `design.py:248`, `design.py:263`、本リポジトリ `CAMERA_JIG.md`。

### F-03 / P1: ねじが描かれておらず、工具アクセスにも反例がある

新設部の実ねじ・ナット・工具がアセンブリの衝突対象に存在しない。
同軸の穴と溝があることは、頭が座る・ナットを保持できる・締められる証拠ではない。

追加検証では、**軸径6 mm×長さ60 mm、柄径20 mm×長さ30 mm**の
仮定ストレートドライバーを、座面から2 mm離した位置から光軸前方へ配置した。
これは未購入の仮定工具で、L形六角レンチ・指・連続挿入軌跡の検査ではない。

| 対象 | 組立後の交差対数 | 新マウントとカメラだけのベンチ状態 |
|---|---:|---|
| カメラM2 / u=-14, v=-14 | 9 | 交差なし |
| カメラM2 / u=-14, v=+14 | 2 | 交差なし |
| カメラM2 / u=+14, v=-14 | 1 | 交差なし |
| カメラM2 / u=+14, v=+14 | 0 | 交差なし |
| キャリアM3 / u=-12 | 13 | 軸とブリッジが0.6148 mm³交差 |
| キャリアM3 / u=+12 | 4 | 交差なし |

組立後は6箇所中5箇所で指・サーボ等に干渉。M3片側はベンチ上でも問題が残る。
より細い工具や別の組立順なら成立する可能性があるため、**あらゆる方法で組立不能とは断定しない**。
しかし現行の組立説明だけでは、ユーザーが締結できることは示せていない。

改善: ねじ・ナット・ワッシャー・実工具を選定し、先付け/後付け/保守を分けて
座面、頭部、ねじ先端、有効かかり、底付き、対向保持、挿入・回転・抜去を検査する。
M3の工具空間は、固定点の外出し・接近方向変更・局所逃げを比較して確保する。
支柱全体を削って辻褄を合わせない。

ROBOTISも、取付穴の深さに対するねじ長の確認を要求している。
[公式のフレーム・ホーン組立注意](https://emanual.robotis.com/docs/en/dxl/x/xl430-w250/#precaution-of-frame-and-horn-assembly)。
「元ねじを4 mm長くする」だけを確定BOMにしてはいけない。

根拠: 受領 `design.py:149`, `design.py:168`, `README_ja.md` §5、
追加検証 `audit.json` の `tool_access` と `tool_envelopes.png`。

### F-04 / P2: 新規ジョー機構ではなく、既存の固定指＋回転指を再配置した案

受領案で新しく作られたのはブリッジ・キャリア・スペーサの3点のみ。
既存の指とサーボ保持部は直接再利用されており、両指の平行移動機構ではない。
開閉で可動指の向きが変わり、把持中心が移動する。平行把持が要求なら未達。

ただし、最新の「ジョー型」という語だけから平行移動必須とは再断定しない。
元のMini Max参照・本リポジトリの保留中の要求草稿とは差があるので、
**固定指＋回転指も許容するのかを明示してから機構を選ぶ**。
原形保存は既存リンクを守る制約であり、新規グリッパ設計を放棄する理由ではない。

改善: 対象物、開口幅mm、把持力N、指長、速度、滑り・把持中心移動の許容を決め、
平行機構と既存回転ジョー案を比較する。ID5は後の指示でロール軸候補になったため、
保留前の「ID5を開閉駆動に使う」草稿を無条件に復活させない。
ロールと開閉をどの実機モーターで担うかを確定する。CADの6モーターと通信IDを混同しない。

根拠: 受領 `design.py:232`, `design.py:255`、`intent/design_intent.yaml` objective。

### F-05 / P2: 接触面の検査が、実際の相手面との接触検査になっていない

`check_interfaces()` は無限軸へ投影した穴中心を照合する。
`flange_material_at_both_seats` はブリッジ自体の薄い断面に材料があるかを見るだけで、
ホーン/固定指の実際のトリム面と接触面積を求めていない。
軸方向に離れた部品でも穴中心の投影は同じである。

追加の不良対照では、キャリアを光軸に沿って後方へ10 mmずらしたものを検査する。
その結果、ブリッジとキャリアの最短距離が0から**2.856911 mm**へ離れても、
`check_interfaces()` はPASSした。設計された接触が失われたことを検出できていない。
これはinterface検査単体の弱点を調べるもので、ハッシュを含む全ゲートを突破するという主張ではない。
確定値は下の検証表と `detached_carrier_negative_control` を参照。

改善: 穴パターン一対一対応に加え、**法線、軸方向の座面位置、トリム面接触面積**を
別々に検査する。正しい穴だが浮いている部品、逆面、埋まった穴、長すぎるねじをREDにする。
円筒面の内外はトポロジーのREVERSEDフラグだけで判断せず、既存の
`cadre.probes.cylinder_surface_sense` を使う。

根拠: 受領 `review.py:118`, `review.py:141`, `review.py:157`。

### F-06 / P2: ソリッドでない46要素が干渉判定から落ちている

167末端要素のうち、ソリッドを持つoccurrenceは121、含まれるソリッド数は123。
残る**46要素はソリッドがないため `broad_pairs()` で除外**される。
ケースカバーやねじのサーフェスが含まれ、単に空の要素というわけではない。

追加した既知の箱＋交差する箱シェルの反例でも、シェルは候補に入らずPASSした。
これは「全ソリッド」検査という実装範囲には整合するが、全実部品の非干渉証明ではない。
新ブリッジと除外面の包絡箱が重なる候補は4件。包絡箱の重なりだけで実干渉とは断定しない。

改善: occurrenceごとにsolid/shell/wire/emptyを台帳化する。
実体がない部品はメーカー実体CADへの置換、表面交差/距離判定、根拠付き保守包絡のいずれかで扱う。
未解決はUNKNOWNとし、無条件に外部干渉ゼロへ合算しない。モーター内部の116ペアは
別集計を維持し、外部46要素の問題と混同しない。

根拠: 受領 `review.py:42`、追加検証 `non_solid_occurrences`,
`shell_obstacle_negative_control`, `new_part_vs_omitted_surface_bbox_overlap`。

### F-07 / P2: 視野・PLA剛性・配線の合格は未成立

カメラの32 mm角基板、レンズ、水平60度/垂直45度画角、光学中心は仮定で、USB端子を持たない。
[参照元の組立説明Step 9](https://github.com/roboninecom/SO-ARM100-101-Parallel-Gripper/blob/305ad0f6e8f19e4e739616160cbdc7cae1ab153f/docs/assembly-guide.md#step-9-camera-attachment-optional)
が指定する28×28 mm穴ピッチだけでは、これらの仮定を裏付けられない。
51姿勢の可視性判定は「指定した指先領域が仮定画角に収まり、各指に8点以上の
可視サンプルがある」ことであり、把持物や接触箇所が実画像で読めることではない。
長い支柱で視野を確保した一方、剛性・振動・質量・ケーブル牽引の評価がない。

ブリッジ根元は6×4 mmの2本ロフト、M2ナット溝底の残厚は公称1.2 mm、
M3ナット溝底は公称1.5 mm。これだけで破損すると断定できないが、PLAの積層方向・
締付け・保持時間を無視して強度合格にはできない。
光学中心とフランジ中心の距離は約54.26 mm。これは重心距離ではなく、荷重計算への代用は不可。

改善: 型番確定までは交換板だけを標準化し、レンズ/端子/ケーブル/部品高さを未知として保持する。
実画像で指だけでなく把持物・接触域・最短撮影距離を確認する。
必要視野を満たす最短の支持形状、根元フィレット/リブ、印刷方向を比較し、
ねじ締結coupon・静荷重保持・ケーブル牽引後の画像ずれを試験する。
プリンタ条件はユーザー確認済みのEnder-3 Pro / 0.4 mm / PLAを引き継ぎ、再質問しない。
今回のZIPにはG-codeがなく、STLの成立をスライス済みと扱わない。

根拠: 受領 `design.py:138`, `design.py:154`, `design.py:171`,
`design.py:187`, `vision.py:79`。

## 3. 改善の実行順と受入条件

| 順 | 作業 | 完了条件 |
|---|---|---|
| 1 | 基準CAD・実機ID・機能を確定 | 全XL430、ID4/5とCADの対応、ロールと開閉の担当、カメラ親部品が一意。旧混在案は参照のみ |
| 2 | グリッパ仕様を決定 | 平行/回転方式、対象物、開口mm、把持力N、指長、速度、保持時間が定義され、未確定を数値捏造しない |
| 3 | インターフェースを先に検証 | 同一assembly座標の穴・軸・座面・支持幅を照合。2 mmずれ/浮き/逆面の負例がFAIL |
| 4 | カメラ取付を局所改修 | P05固定を基本案に交換式キャリアを統合。ロール追従へ変えるなら明示承認。mask外形状・元ねじの機能は保存 |
| 5 | BOMと組立工程を実体化 | 実ねじ・ナット・工具・固定相手・順序をCADに入れ、頭/底付き/かかり/工具/対向保持/挿入・抜去が成立 |
| 6 | 組立と動作の回帰 | solid以外も台帳に含む。全干渉ペア、ジョー開度、承認した手首姿勢、配線包絡を検査。未検査はUNKNOWN |
| 7 | 実カメラとPLAを評価 | 把持域の実画像、USB挿抜/曲げ/引張、支持剛性・ねじ保持・クリープを確認 |
| 8 | 印刷と実機試着 | couponを先に測定。承認部品のみ1プレートへ配置しG-codeを再検査。印刷合格と運用合格は別 |
