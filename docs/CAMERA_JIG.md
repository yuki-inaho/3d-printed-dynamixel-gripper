## 目的と対象

グリッパ開発に先行し、ユーザー提供写真で示された白いリンクへ
SO-ARM101参考設計と同等のカメラ取付を追加する。写真ではID5未装着。
リンク本体の輪郭、ホーン穴、モーター取付穴は変更しない。

写真の「丸いホーン取付端から伸び、先端がコの字になる部材」は
同梱R3 CADの `P05_wrist_XL430.step` と外形が対応する。
R3のJ4は曲げ、J5はロール、J6はグリッパ。実機の通信IDは読み取っていない。
カメラはP05に固定するので、J4とともに動くがJ5出力のロールには追従しない。
写真による部品対応と、シリアルIDの実測は区別する。

ユーザー回答により、**中央つなぎ板はCAD値の厚さ4.0 mm・横幅46.0 mmで設計する**。
設計開始のための追加採寸は要求しない。印刷誤差・保持具合は試着時に確認する。

## 参考と座標

- R3入力: `references/arm-r3/`。受領アーカイブの展開内容とSHA256記録は
  候補出力の`validation.json`に保存。
  入力SHA256は出力 `validation.json` に保存。元アーム自体の運用合格は主張しない。
- カメラ入力: Robonine
  [assembly-guide Step 9](https://github.com/roboninecom/SO-ARM100-101-Parallel-Gripper/blob/305ad0f6e8f19e4e739616160cbdc7cae1ab153f/docs/assembly-guide.md#step-9-camera-attachment-optional)。
  28×28 mm四穴、M2、標準UVCカメラ。RealSenseではない。
- 同コミットのSTEP、スペーサ、ライセンスは `references/robonine/`。
  スペーサは形状変更なし。参照カメラとスペーサはB-rep上で28 mmと34 mmの両パターンを持つ。
  ジグが使用するのは28 mmのみ。外側の未使用穴は誤配置ではない。

すべてmm。R3保存姿勢のworld座標を使う。
P05 bbox: X[-23.2,22.8], Y[91.4,174.9], Z[151.1,196.6]。
中央板はY[140.4,144.4]。カメラ面原点=(-0.2,139,228)、local→worldは
X回り-120度回転後に原点へ並進。光軸=(0,0.8660254,-0.5)。
30度下向きは今回の仮設計値であり、ユーザー指定の視野角ではない。

## 構成と荷重経路

| 部品 | 構成 | 数 |
|---|---|---:|
| saddle | 後側クランプ、上縁ストッパー、支柱、カメラ取付枠を一体化 | 1 |
| front_jaw | 前側押さえ板。モーター支持側板を挟まない逃げスリット | 1 |
| camera_spacer | Robonine由来の38×38×2スペーサ | 1 |
| カメラ固定ねじ | M2×10とナット、未選定の公称包絡モデル | 各4 |
| クランプねじ | M3×16とナット、未選定の公称包絡モデル | 各2 |

カメラ枠は38×38×3、開口23×23、穴φ2.4、中心(±14,±14)。
M3二本はX=-28.7,+28.3、Z188.6で中央板の外を通す。
前後から中央板を挟み、ホーン両側の腕をX方向へ押し縮めない。
前板の二つの逃げは幅4.5、対応する側板厚4.0。締付量は分割板で調整する。
公称接触での設計であり、締付トルク・PLA摩擦・クリープ寿命は未評価。

ねじ長の仮定: カメラ積層6.5 + ナット1.6、M2×10の突出1.9。
クランプ積層10.0 + ナット2.4、M3×16の突出3.6。
ワッシャーなしの検討値。追加する場合は積層とねじ長を再計算する。
参考ページのM2×8を無条件に流用しない。頭部・工具・ナット型番は未購入/未選定。

## 組立順序とアクセス

1. アームから離したsaddleへスペーサとカメラをM2で先付けする。
2. カメラ付きsaddleを中央板の上から下ろす。
3. front_jawを側板の逃げに合わせて上から下ろす。
4. M3二本で前後を固定する。変形させる強締めはしない。保持力評価は別途必要。
5. 配線を確認してからID5を組む。写真の現状ではID5がないので先付けしやすい。

**装着後にすべてのカメラねじを外せる設計ではない。**
保存姿勢ではカメラねじの直線工具経路がアームに当たる。
工具チェックは「全組立状態」と「ベンチ先付け」「クランプ締付け」を分け、
全組立状態のFAILを残す。工具は軸75 mm、ハンドルφ20×30などの仮定で、実工具の保証ではない。
指の空間、レンチ回転掃引、ビットのかかり、連続挿入軌跡は未評価。

## 再現

リポジトリ: project root (`3d-printed-dynamixel-gripper`)。
既存出力は上書きしない。次のrun名は未使用の名前にする。

```bash
rtk proxy uv sync --locked
rtk proxy uv run pytest -q
rtk proxy uv run ruff check camera_jig scripts tests
rtk proxy uv run python -m camera_jig.build --out outputs/camera-jig-next
rtk proxy uv run python -m camera_jig.serviceability outputs/camera-jig-next
```

buildのexit 0は限定的な静的幾何検査の合格。印刷承認ではない。
serviceabilityのexit 2は全組立状態の工具アクセスFAILを含むため、現設計では期待する結果。
最新サービス検査は `serviceability-r3.json`。不良初期工具モデルの記録も保持する。
カメラ機種、コネクタ、ケーブル曲げ半径/固定、視野、可動範囲が確定したら次の設計検証へ進む。
