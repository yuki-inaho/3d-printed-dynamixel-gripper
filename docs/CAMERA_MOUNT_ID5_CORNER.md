# ID5モーター上方カメラ取付の設計要求

更新: 2026-09-24。これは次のCAD設計作業へ渡す要求・設計基準であり、完成設計や製作承認ではない。
実行手順は`temp/workdoc_Sep24-2026_camera_mount_id5_corner.md`、機械可読要求は
`specs/camera_mount_id5_corner.yaml`。

## 1. ユーザー目的

ID5を開閉用に使うPG3平行グリッパで、左右の爪と把持対象キューブが見えるようにする。
既存のP05リンク側から横へ張り出すカメラ配置は見た目の意図に合わない。新案はID5モーターの
コーナーねじ付近を利用し、カメラをモーターより上に置いて把持域を斜め下へ見下ろす。

確定済み: ID5はグリッパ開閉、追加モーターなし、ロール不要。カメラは未購入だがSO101参考と
同等の28x28 mm四穴を維持する。対象物はキューブだが一辺と重量は未定。

## 2. 現状と設計上の差

現在の`camera_jig/`と`specs/camera_mount.yaml`はP05を親とする旧側方案で、ソース変更は許されていない。
旧案は再現・回帰用に保つが、新しい取付位置として流用したり、小移動だけで今回の要求を満たしたと
扱ったりしない。`gripper_design/pg3_id5.py`、`gripper_design/architecture.py`と
`specs/architecture.yaml`にも旧カメラ親の実装契約がある。新候補は別builder/spec/testとして実装し、
旧契約を意図的に置き換える際は変更内容と回帰影響を記録する。

調査の出発点:

- 原アーム: `references/arm-r3/arm_XL430_R3.step`。
- 現在のID5開閉全腕候補: `outputs/pg3-id5-p05-windows-r2/ID5_mid_P05_windows_CANDIDATE.step`。
- 同候補の受入記録: `outputs/pg3-id5-p05-windows-r2/review.json`。
- 3開度の一つ前の候補: `outputs/pg3-id5-only-r1/arm_camera_{open,mid,closed}_ID5_CANDIDATE.step`。
- 元PG3部品: `references/pg3-c9/PG3_C92_J28/CAD/parts/`と対応する`STL/`。
- 旧P05カメラ案のコード/図: `camera_jig/`, `outputs/camera-jig-20260922-r11/`。
- カメラ穴の参考とライセンス: `references/robonine/`, `docs/CAMERA_SELECTION.md`。

全腕mid候補は1806 PASS / 1 ERROR / 6 UNKNOWN / 0 FAILで、`fabrication_approved=false`。
エラー/unknownをカメラ変更で消えたことにせず、同じ入力組立の比較条件を保つ。
CADラベルM05は物理ID5を実測で証明しない。新設計はユーザーが指したID5位置の候補を対象とし、
物理ID-CAD occurrence対応は未確認と明記する。

## 3. 設計境界

取付先はID5サーボの回転出力ホーンではなく固定ケース側。コーナーのねじがケースを締結する
タイボルトなのか、外部ブラケットを受ける取付穴なのかをCADと公式寸法で区別する。
長いねじへの置換はケース締結を弱めたり、ねじ底付き/内部接触を起こす可能性があるため、
ねじ長・有効かかり・頭座・工具・ケースクランプ機能を確認するまで設計寸法を確定しない。
モーターや元アームへの新規穴あけ、元CAD形状の変更はしない。

### CADアンカー調査 (2026-09-24、設計候補であり取付承認ではない)

ROBOTISの[XL430-W250新型図面](https://emanual.robotis.com/docs/en/dxl/x/xl430-w250/#drawings)は、ケース角の皿ねじと、上面の`4-phi2.1 HOLE DP4.0(MAX.)`を別に示す。
角の皿ねじは既存ケース締結を担う可能性があり、カメラ荷重の共用アンカーとしては未承認。
カメラをモーター上から斜め下へ向ける新候補では、ケースを開かずに使える上面の既存フレーム取付穴を第一候補とする。
ユーザーの「角ねじあたり」の位置要求は保ちつつ、ねじ機能の混同を避ける設計選択である。

保存済み全腕mid STEPの`PG3_XL430_fixed`と元アームの`M05_ref00`で、凹円筒面4本を独立抽出した。
組立座標(mm)で穴中心は`x=-8.2,7.8`と`y=158.9,170.9`の直積、上面`z=199.85`、
円筒径`phi2.1`、円筒部`z=195.85..199.65`。入口の0.2 mmは別形状であり、
図面の最大深さ4.0 mmをねじの許容挿入長と同一視しない。
ケース角のねじ位置候補は局所座標`x=+/-11,y=-32/8,z=+/-17`で、上面取付穴とは異なる。
`P05`の最大zは196.6 mm、現PG3フレームの最小yは181.9 mmで、上面穴中心とは離れるが、
取付板・ねじ頭・工具・配線を含むクリアランス合格は別途必要。
`camera_jig/id5_corner_anchor.py`と`tests/test_camera_jig_id5_anchor.py`が座標の正負例を検査する。

視野の一次スクリーニングでは、仮光学中心`(-0.2,178.0,226.0)`から
`(-0.2,214.6,164.6)`を見る約59.2度の下向き視線を候補とした。
50度の仮垂直FOV・4:3で開/中/閉の両パッド外接箱が画面内、フレームAABBを横切る
外接箱角への光線は0/48本。ただしこれは外接箱による保守的な診断で、B-rep遮蔽、
カメラ筐体/ホルダ/ケーブル、実FOVと焦点の合格ではない。
20 mmキューブは全開でのみ、10 mmは全開/中間でのみ名目パッド間に入る。
閉状態の0.9 mmギャップにキューブを重ねて「見える」とは扱わない。
証拠は`outputs/camera-mount-id5-corner-vision-r4/`のJSON/3姿勢図。

カメラ基板外形、光学中心、レンズ突出、FOV、質量、USB端子とケーブルはすべて未確定。
28 mmは穴ピッチだけで、カメラ本体サイズや視野を決めない。仮カメラを使うときは
寸法/FOVの根拠と感度範囲を記録し、視野の合格とは区別する。

固定ケースとカメラの相対姿勢を保ち、左右パッドとキューブの把持領域を開/中/閉で評価する。
下向き視線の角度・高さ・前後位置は候補比較で決め、事前に固定値を捏造しない。
10/20/30 mmキューブは既存プロジェクトの診断用比較に限り、ユーザー要求寸法にしない。
仮想センサだけでなく、筐体/板/ねじ/工具/配線を同じ剛体変換で追従させる。

## 4. 必須検証

1. CAD B-repで対象ケース角ねじの中心、軸、座面、穴/ねじの形状範囲を独立に特定し、その機能を出典付きで分類する。
2. カメラ板28x28 mmパターン、穴径、座面、部品方向、STEP再読込後形状を検査する。
3. モーターケース/ホーン/グリッパの開・中・閉と対象アームとの衝突を区別し、元からある干渉・ERROR・UNKNOWNを保存する。
4. ケースねじの締結スタック、ケース固定力維持、ねじ底付き、ビット挿入/回転、組立順序と保守アクセスを検査する。
5. ID5ケーブルとカメラケーブル/コネクタのルート、動作時曲げ、抜き差し経路をモデル化する。実寸不明はUNKNOWN。
6. カメラの高さ/角度を掃引し、把持対象・両パッド・指・リンク・モーター・取付具・配線ごとの遮蔽を記録する。
7. 腕への追加質量、重心/レバー腕、PLA部品の荷重経路・最小断面を提示し、材料値/負荷がない強度はUNKNOWNとする。
8. 独立STEP/STL再読込、静的シーン/CLI検査、Playwright + Chili3Dのheadless画像とDOMを同じSHAの版に揃える。

テストは設計実装前に追加し、誤アンカー、誤ピッチ、センサのみ移動、ケース/ホーン衝突、工具アクセス不足などの負例をREDで確認する。
閾値や対象集合を狭めて既存ERROR/UNKNOWNをPASSにしない。
